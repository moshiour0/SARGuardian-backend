## PR #48 — promising target-free GUNW path, not yet a release

Branch: `feat/dynamic-goff-reference-timeseries`  
Head: `cd96e7ac53cce543ea5387fab27510c898f6da19`  
State: open, draft. Base is an older backend main revision (`8f5bcf1...`), not current main.

### Useful additions
- `dashboard/aoi_displacement_candidates.py`: target-free spatial anomaly candidates over retained GUNW/GOFF exports, grouped by exact network identity and metric family. GUNW LOS and GOFF offsets remain separate. It refuses malformed product/AOI/grid contracts and requires repeat support at the same pixels before labelling a recurrent candidate.
- `dashboard/aoi_relative_pixel_timeseries.py`: target-free GUNW per-pixel LOS inversion. It requires a connected network, >=3 unique pairs, >=1 cycle redundancy, >=200 common valid pixels, same exact grid and >=200 non-candidate background pixels. It removes a median over the AOI-derived background for each pair, inverts pair edges to epochs, and exports LOS velocity, fit-sigma, closure-RMSE and per-epoch rasters.
- `prepare_web_assets.py`: derives web map layers from those output GeoTIFF artifacts. Unit tests check the velocity layer is exposed separately. Candidate polygons are inserted into the map as GeoJSON.
- New tests cover a target-free redundant temporal network, no-target eligibility, no-redundancy withholding, recurrent same-pixel spatial candidates, GOFF's non-ground-motion label, bad export contracts and dashboard derived-layer exposure.
- The branch's CI check-runs on the inspected head were all successful (5/5), including a retained-artifact reassembly E2E check on 2026-10-28. This is a code/test result on that historical branch/base, not independent geophysical validation and not proof it works on today's main without rebase/retest.

### Critical scientific limits
1. The GUNW reference is derived from pixels in the AOI; it is not independently validated stable ground. The code explicitly warns that pairwise median removal suppresses a spatially uniform AOI-wide movement component. Thus it can map local deformation relative to an assumed background, but cannot detect common translation of the entire AOI.
2. The minimum of 200 common pixels is a raw count, not an effective independent sample size. Spatially correlated pixels may represent far fewer independent observations; distribution over the AOI and alternative-reference sensitivity should be measured.
3. The graph inversion uses an unweighted pseudoinverse. Pixelwise fit sigma/closure residual do not include atmosphere, orbit ramps, phase unwrapping, reference drift, spatially correlated error or per-edge variance/covariance.
4. Candidate score thresholds (robust z 4.5, local median-filter window 11, repeated same-pixel support 2) are not yet calibrated against held-out spatially correlated null scenes and known-motion injections. Broad smooth signals may be removed by AOI median/local-background subtraction.
5. Candidate outputs in this new module are JSON/GeoJSON/CSV; the candidate polygons display on the map, but a dedicated georeferenced candidate-mask/count/coherence raster and matching scientific PNG quicklooks are not generated by this module.
6. This PR's `goff_common_reference.py` is target-dependent: it returns `BLOCKED_NO_VALID_IN_AOI_TARGET` unless an explicit in-AOI measurement target is present, and excludes a 2 km target buffer. Keep this component outside Find Displacements; it belongs to a target-selected analysis path.
7. A GOFF pairwise offset anomaly or graph-inverted range/azimuth offset series is not a ground-motion velocity unless image offset semantics, geometry, units and uncertainty support that physical interpretation. Do not mix it with GUNW LOS millimetres.

### Release requirements for PR #48
- Rebase onto the current backend main (which includes the retry-products merge) and rerun all checks, including retained-artifact E2E.
- Keep `goff_common_reference.py` gated out of target-free Find Displacements, or clearly mark it as an independent Known Place-only optional stage.
- Add per-pixel or per-measurement uncertainty/covariance weighting where product layers support it; at minimum preserve and publish GOFF range/azimuth variance and SNR/correlation provenance.
- Add spatially correlated null and multi-scale known-displacement injection tests, multiple-testing/false-alarm calibration and effective-reference-sample diagnostics.
- Generate candidate mask/count/directional-support GeoTIFFs (and PNG quicklooks) with exact AOI hash, CRS, transform, units, support and checksums.
- Preserve the explicit statement that the reference is AOI-derived and relative-only. Do not label it absolute ground movement or a validated hazard.

**Verdict:** strongest current prototype for target-free GUNW temporal velocity and map-layer wiring, but PARTIAL / NOT RELEASE-READY for operational claims.

## PR #49 — output formatter, not a target-free estimator

Branch: `feat/find-displacements-science-measurements`  
Head: `4b4fee13976019741a115004cde9b9a0d0b76d16`  
State: open, draft. Base is also an older backend main revision.

Adds `observed_movement_measurements.py`, which only summarizes components already marked `DIAGNOSTIC_SERIES_AVAILABLE_REFERENCE_UNVALIDATED`; it requires >=3 actual strictly increasing epochs, refuses duplicate/unordered/nonfinite records, and does not promote pairwise medians. GUNW LOS and GOFF offset families are kept separate. These are good output guards.

However, it consumes `common_reference_report` and `goff_common_reference_report`. In the inspected branch both upstream common-reference implementations require explicit target coordinates, so this formatter cannot create target-free Find Displacements measurements by itself. The tests verify the formatter and explicitly check empty output when upstream references are blocked; they do not establish target-free physical measurements.

**Verdict:** useful downstream reporting component, but NOT sufficient for Find Displacements by itself. Integrate only after a target-free estimator is the actual upstream data source.

## Overall decision

Do not merge or repurpose PR #48/#49 solely because their tests are green. PR #48 provides the right *architecture direction* for target-free GUNW LOS velocity, while its reference, uncertainty and false-alarm validation still need work. Keep existing Known Place target-dependent modules and their semantics unchanged.
